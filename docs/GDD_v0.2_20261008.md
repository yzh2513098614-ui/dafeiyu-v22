# AI拟人 2.5D 卡牌搜打撤游戏设计总纲

**Game Design Document · GDD v0.2**

项目状态：概念设计与战斗原型规划阶段  
游戏名称：暂定  
开发引擎：Godot 4.x  
游戏类型：2.5D自由探索 / 卡牌战术 / 搜打撤 / Roguelite / AI拟人  
初期模式：单机 PvE  
后续扩展：避难所经营、角色养成、剧情、多人模式

# 第一章：游戏总体定位

## 1.1 核心概念

本游戏是一款以人工智能拟人为世界观主题，将2.5D空间探索、隐藏敌人遭遇、卡牌指令编排和搜打撤风险管理结合的独立游戏。

玩家操纵拥有不同系统能力的AI拟人角色，进入废弃的数据设施、研究机构、城区、地下网络和异常空间，通过探索建筑、搜索容器、获取情报、回收物资和解决遭遇积累资源。

敌人并不总是直接显示在地图上。

玩家可能只能发现黑暗房间中的模糊轮廓、异常声音、闪烁的指示灯和危险痕迹。

在无法完全确定敌人数量、位置与能力的情况下，玩家需要决定是否进一步侦查、进入房间、进行战斗，或者直接绕路离开。

遭遇战斗后，玩家通过卡牌提前安排一组指令，并与敌方指令同步结算。

最终目标不是击败所有敌人，而是带着有价值的物资成功撤离。

## 1.2 一句话定位

**在未知的数据废墟中，编排AI角色的行动程序，搜索珍贵资源，并设法活着撤离。**

## 1.3 核心特色

1. **真实2.5D探索**：角色能够在复杂立体建筑中自由移动、搜索、绕路和寻找撤离点。
2. **非显示怪机制**：敌人通常隐藏在暗处，通过声音、轮廓和环境线索逐步暴露。
3. **卡牌编程式战斗**：玩家排列指令，双方同步执行，卡牌顺序决定战术效果。
4. **空间战术**：门、墙、家具、掩体、高低差和通道影响卡牌结算。
5. **AI拟人世界观**：卡名、敌人、状态、技能和资源与编程、LLM和计算机系统密切关联。
6. **搜打撤经济**：资源获得、死亡损失、装备成本和撤离风险共同形成决策。
7. **低动作成本演出**：使用Q版人物、Sprite3D、数据特效和指令执行动画，避免大量复杂骨骼动作。

## 1.4 核心设计原则

**玩家的主要目标是完成一次有价值的撤离，而不是清空地图。**

因此：

- 战斗应该可以主动回避。
- 遭遇后应该存在脱离的可能。
- 战斗胜利应当具有资源成本。
- 获取信息应当具有战略价值。
- 高价值物资会改变玩家对风险的判断。
- 不确定性必须具有可学习的规律，而不能完全依赖随机惩罚。
- 每个复杂系统都应直接服务搜索、战斗或撤离体验。

# 第二章：AI拟人世界观

## 2.1 世界设定

游戏发生在一个由人工智能、自动化设施和数字意识共同构成的架空世界。

某次大规模系统异常后，原本正常运行的城市、实验设施和数据网络逐渐失去控制。

不同AI实体发生了不同程度的上下文漂移、记忆损坏、权限冲突和异常行为。

世界留下大量未被回收的计算资源、模型权重、训练数据、存储核心和历史记录。

部分区域已经完全失联，部分区域仍由自动化守护程序控制。

玩家扮演能够独立行动的AI拟人角色，进入这些危险设施，收集资源并探索异常的来源。

本作中的技术术语是世界观的艺术化解释，并不要求所有游戏机制严格对应现实计算机技术。

## 2.2 世界观关键词

| 技术概念 | 游戏化含义 |
|---|---|
| Token | 基础数据资源或技能弹药 |
| Context | 上下文容量、战斗记忆 |
| Compute | 算力，发动卡牌的主要资源 |
| Integrity | 系统完整度，相当于生命 |
| Trace | 追踪痕迹、系统警戒 |
| Attention | 注意力、感知与目标识别 |
| Hallucination | 幻觉、假情报、异常敌人 |
| Prompt Injection | 指令注入与控制 |
| Rollback | 回滚与状态恢复 |
| KV Cache | 技能缓存与复用 |
| Firewall | 防御屏障与区域封锁 |
| OOM | 内存溢出与超负荷状态 |
| Checkpoint | 战术检查点 |
| Exit(0) | 安全退出与撤离 |

## 2.3 AI拟人角色设计

角色以日式二次元Q版和萌系AI拟人为主，采用蓝白色为主要视觉基调。

不同角色具有独立的人格设定、系统背景和战斗特长。

例如：

**推理型AI**：擅长预测敌方行动，拥有更多侦察和分支指令。

**安全型AI**：擅长防御、异常捕获、权限管理与防火墙。

**攻击型AI**：擅长高算力输出、数据爆发和快速连续指令。

**轻量型AI**：算力成本低，移动和撤离能力强。

**异常型AI**：擅长幻觉、污染、干扰和错误指令。

人物性格与能力可以关联，但不应该限制玩家只能使用固定流派。

# 第三章：玩家核心循环

## 3.1 单局循环

准备卡组和装备  
↓  
选择进入区域  
↓  
2.5D自由探索  
↓  
搜索房间和容器  
↓  
发现环境异常或隐藏威胁  
↓  
判断侦查、绕路、接敌或撤退  
↓  
进入指令卡牌战斗  
↓  
击败敌人或成功脱离  
↓  
获取战利品  
↓  
评估当前收益和危险  
↓  
继续探索或前往撤离点  
↓  
处理撤离阶段的潜在遭遇  
↓  
成功撤离，结算战利品

若死亡，则按照资产保护规则损失部分或全部本次携带物资。

## 3.2 单局体验目标

一场普通探索局建议以10～20分钟作为初始测试范围。

玩家不应该每次进入房间都遭遇战斗。

理想情况下，一局应当包含：

- 数次有意义的容器搜刮。
- 多次观察环境和判断潜在危险。
- 少量普通战斗或可绕过的遭遇。
- 一至两次重大风险决策。
- 一次具有不确定性的撤离过程。

具体节奏需要通过实际测试调整。

## 3.3 长期循环

撤离成功  
↓  
战利品入库  
↓  
制作装备、解锁卡牌、修复物品  
↓  
调整角色能力与卡组  
↓  
进入更危险区域  
↓  
寻找稀有资源和特殊敌人  
↓  
逐步推进世界探索与剧情

避难所建设可以在后续版本加入这一循环，但不是最初战斗Demo的必要条件。

# 第四章：2.5D地图和空间探索

## 4.1 地图形式

探索时不采用传统格子移动。

角色能够通过WASD或鼠标点击在3D空间中自由移动。

游戏使用固定或可控角度的2.5D俯视镜头。

地图包含复杂建筑结构：

- U形、L形、T形建筑。
- 多层楼梯与回廊。
- 商场中庭与挑空空间。
- 研究设施与实验室。
- 大型仓库、货架和物流区。
- 地下管线、维护通道和隐藏房间。
- 可访问的室内外连接区域。

## 4.2 地图的游戏性

地图不应只是装饰。

每张地图至少需要包含：

**搜索功能**：不同区域具有不同价值的容器和资源。

**路线功能**：存在安全但较远的路线，以及危险但资源密集的路线。

**战术功能**：提供掩体、门、障碍、楼梯、狭窄通道和高低差。

**信息功能**：利用灯光、声音和环境痕迹提示潜在危险。

**撤离功能**：设置具有不同条件和风险的撤离点。

## 4.3 容器系统

容器可以分为普通容器、高级容器、特殊设备和事件容器。

例如：

普通储物柜、服务器机柜、实验样本箱、数据终端、加密保险柜、维修工具箱和权限锁房间。

每类容器使用独立掉落表。

一些容器需要工具、权限、特定角色能力或探索卡牌才能高效开启。

容器内可以出现资源，也可以触发异常事件。

## 4.4 地图扩展方向

可以优先利用已有设计中的学校、研究中心、博物馆、行政中心、物流港、地下服务区等地图类型。

但初期应先制作并验证一张完整研究设施地图，不急于同时推出大量地图。

# 第五章：暗房与非显示怪系统

## 5.1 基本规则

敌人不总是以完整角色模型存在于探索视野中。

玩家可能通过环境信息感知敌人：

异常声音、模糊轮廓、影子、眼睛、脚印、损坏设施、闪烁灯光和异常信号。

玩家能够依据这些信息判断房间是否值得进入。

## 5.2 三层信息状态

### 第一层：未知

玩家只能看到环境异常。

不知道敌人种类、数量与准确位置。

### 第二层：半识别

玩家获得部分情报，例如：

大型生物轮廓、疑似机械单位、两个声源、缓慢移动目标。

可能显示一片区域，而不是一个精确坐标。

### 第三层：完全识别

通过扫描、接近、战斗观察或特殊技能，揭示敌人名称、已知弱点、战术位置和攻击预兆。

敌人的意图是否能够完全识别，取决于敌方能力及情报等级。

## 5.3 暗房探索决策

玩家靠近暗房，可以选择：

直接进入、倾听、窥视、照明、扫描、放置诱饵、改变路线或者放弃探索。

信息获取可能付出电量、道具、时间或追踪痕迹成本。

因此玩家不是单纯决定打不打怪，而是先决定愿意为情报支付多少成本。

## 5.4 道路遭遇

危险不能全部集中在房间内。

走廊、楼梯、地下通道和撤离路线也可以触发事件。

事件包括：

异常巡逻、系统停电、伏击、门禁锁定、设施故障、幸存AI请求、陷阱和区域警报。

重大危险应尽量通过环境预兆体现。

## 5.5 隐藏遭遇池

每个地图区域拥有一个隐藏遭遇池。

遭遇池包含空事件、普通敌人、稀有敌人、资源事件和特殊异常。

玩家的行为可以改变后续事件的权重。

例如：

大量高噪音攻击增加追踪事件权重。

长期滞留增加高威胁遭遇权重。

完成某些设施控制行为可以降低局部警戒。

这里需要注意：遭遇随机不等于敌人可以不合理地凭空出现。遭遇发生的位置、时机和条件必须符合地图规则。

## 5.6 公平性原则

最重要的原则：

**结果允许随机，但风险必须有迹可循。**

致命事件需要足够的预兆。

玩家应该拥有侦查、规避、准备、防御或撤退的可能。

危险可以难以预测，但不能让玩家无法理解为什么失败。

# 第六章：卡牌系统总体设计

## 6.1 卡牌的本质

卡牌不是简单的攻击按钮。

**卡牌代表AI角色能够执行的操作指令。**

战斗时，玩家通过排列卡牌编排短程序。

探索时，部分卡牌对应常驻工具或技能。

## 6.2 六类核心卡牌

| 类别 | 核心功能 | 示例 |
|---|---|---|
| 侦察卡 | 获取敌人或环境情报 | Data Probe、Attention Map |
| 攻击卡 | 输出伤害、施加标记 | Token Burst、Gradient Descent |
| 防御卡 | 防护、打断、异常免疫 | Firewall、Sandbox |
| 位移卡 | 移动、闪避、换位 | Async Jump、Teleport |
| 控制卡 | 干扰敌人行为或指令 | Prompt Injection、Rate Limit |
| 功能卡 | 缓存、回滚、分支、资源处理 | KV Cache、Rollback、Garbage Collection |

撤离和生存功能可以通过上述卡牌类别实现，不必无限增加分类。

## 6.3 卡牌来源

### 角色固有能力

角色永久拥有的基础能力。

不会因为普通战斗失败而消失。

### 装备提供的能力

装备可以为战斗牌组添加专属卡牌。

例如一件特殊设备提供扫描和干扰技能。

装备失去后，对应卡牌不可继续使用。

### 消耗品

医疗物品、临时算力模块、数据炸弹、诱饵等。

使用时需要消耗真实背包物资。

### 异常状态卡

角色受到污染、损伤和压力时产生。

例如：

Hallucination、Context Overflow、Memory Leak、Corrupted Token。

这些异常可以干扰牌组与指令执行。

## 6.4 探索和战斗的操作区别

探索时不建议要求玩家反复随机抽取开锁卡、扫描卡和照明卡。

探索技能以常驻工具栏形式提供，受装备、资源或冷却限制。

进入战斗后，再从战斗牌组抽取卡牌并编排指令。

如此可以同时保留探索流畅性和卡牌策略性。

## 6.5 建议初始牌组参数

以下均为原型参数：

- 基础牌组：20张左右。
- 初始手牌：5张。
- 手牌上限：7张。
- 基础算力：3点。
- 每个规划窗口最多3个普通指令槽。
- 高级卡牌可能消耗多个指令槽。
- 部分卡牌通过特殊条件获得额外指令。

需要区分卡牌算力消耗与指令槽占用。

例如一张卡可以消耗2算力但只占1个指令槽。

# 第七章：核心战斗机制

## 7.1 系统名称

暂定：

**Inference Combat System｜推理式战斗系统**

核心战斗形式：

**三指令队列 + 同步结算。**

## 7.2 与传统回合制的区别

传统卡牌游戏中，玩家依次使用卡牌，随后敌人行动。

本游戏中：

玩家预先排列指令。

敌人按照自己的行为规则生成指令。

双方的指令进入同一组结算阶段。

玩家和敌人按照规则同时行动。

因此玩家不能假设自己安排的攻击必然先于敌人完成。

## 7.3 三格指令制

每轮规划时，玩家安排最多三个普通指令。

例如：

第一格：Async Jump

第二格：Firewall

第三格：Token Burst

敌人也拥有自己的行动序列。

双方提交以后开始执行。

第一格与第一格同步结算。

第二格与第二格同步结算。

第三格与第三格同步结算。

一次三格执行称为一个战斗窗口。

窗口结束后，更新战场状态，再进入下一次规划。

## 7.4 同步结算规则

初版建议采用离散指令槽，而不是连续秒级时间轴。

每个槽内统一处理：

1. 行动合法性检查。
2. 移动与空间冲突判定。
3. 防御、控制与打断效果。
4. 攻击命中与伤害结算。
5. 状态变化和事件记录。

这只是首版基础结算顺序。

具体需要进一步制定同时移动、相互击杀、打断优先级和目标失效等规则。

双方移动不能简单处理成玩家先移动、敌人后移动。

## 7.5 战斗胜利条件

战斗不要求清除所有敌人。

可能的结果包括：

击败敌人、完成特殊目标、成功脱离、被击败或者特殊事件终止。

## 7.6 战斗脱离

玩家应始终具备基础脱离能力，不应依赖随机抽中逃跑卡。

玩家需要移动到合法出口、执行脱离操作，并在必要条件下抵抗敌人追击。

高级卡牌可以提高脱离效率。

例如：

Graceful Shutdown、Async Jump、Firewall、SIGKILL。

战斗脱离不等于地图撤离。

战斗脱离后玩家仍然处于危险地图中。

## 7.7 敌人指令与公平性

普通敌人在战斗窗口开始时，根据自身状态和已知情报选择行动。

玩家只能看到部分敌方意图。

敌人不能无条件读取玩家已经提交的秘密指令，并以此精准反制。

特殊高级敌人可以具有条件响应、指令中断或反预测技能，但其行为需要符合明确规则。

## 7.8 未来高级机制

### 条件分支

如果敌人发动冲锋，则执行闪避。

否则执行攻击。

### 并行计算

允许某些兼容指令同时执行。

### 异常捕获

当原定指令被打断时，启动备用指令。

### 指令缓存

复用上一条符合条件的已完成指令。

### 回滚

恢复受限制的历史战术状态。

这些属于战斗系统扩展内容。

首版应先验证三指令顺序结算是否足够有趣，再决定加入哪些高级机制。

# 第八章：战斗空间和格子方案

## 8.1 最终推荐方向

**自由探索 + 隐藏战术格子。**

地图不强制格子化。

战斗逻辑使用局部离散空间。

只有玩家规划指令时才显示必要的战术网格、目标格和危险范围。

执行阶段格线可以淡出。

## 8.2 原型设计

初期可以测试：

8×8局部战斗网格。

单格边长暂定1.5米。

基础位移一次可移动最多2格。

具体参数需依据角色大小、地图比例和操作手感调整。

## 8.3 地形规则

逻辑格子需要具有：

可通行、阻挡、掩体、可破坏、危险区域、交互对象和楼层高度等属性。

真正的墙体和家具仍由3D场景表现。

格子只是用于战斗空间判断。

## 8.4 同步位置变化

双方同时移动时，需要确定：

- 是否争夺同一位置。
- 路径是否被其他单位阻挡。
- 交换位置是否允许。
- 位移技能能否穿越障碍。
- 目标离开攻击范围以后攻击如何处理。

这些应由确定性规则处理，不依赖人物动画碰撞时机。

## 8.5 战术节点备选方案

另一种可测试方案是少量固定战术站位点。

例如：

门口、实验桌后、货架旁、控制台前、楼梯口。

玩家通过卡牌在这些节点之间移动。

优点是减少位置选择与复杂动画。

缺点是空间自由度可能不足。

首版先测试隐藏格子，再比较战术节点模式。

# 第九章：AI主题卡牌命名与机制

卡名应该与效果存在直接的语义关联，避免只有名字与AI有关、效果却毫无关系。

## 9.1 首批代表性卡牌

| 卡牌名称 | 中文名 | 主要效果 |
|---|---|---|
| Data Probe | 数据探针 | 获取敌人行动情报 |
| Attention Map | 注意力图 | 揭示一片区域的活动目标 |
| RAG Query | 检索增强 | 获取额外情报或发现弱点 |
| Gradient Descent | 梯度下降 | 连续攻击同一目标逐渐强化 |
| Token Burst | Token爆发 | 快速数据攻击 |
| Firewall | 防火墙 | 形成护盾或阻挡通道 |
| Sandbox | 沙箱隔离 | 防御异常指令或状态污染 |
| Async Jump | 异步跳转 | 快速位移 |
| Prompt Injection | 提示注入 | 干扰敌方行动目标 |
| Rate Limit | 速率限制 | 限制敌方行动频率 |
| KV Cache | 键值缓存 | 复用符合条件的技能 |
| Branch Prediction | 分支预测 | 提前判断敌人行动 |
| Parallel Processing | 并行计算 | 使兼容指令重叠执行 |
| Exception Handler | 异常捕获 | 被打断时执行备用动作 |
| Checkpoint | 检查点 | 保存限定的战斗状态 |
| Rollback | 回滚 | 恢复部分历史状态 |
| Garbage Collection | 垃圾回收 | 清理异常牌和无效指令 |
| Context Overflow | 上下文溢出 | 高输出并产生自身负面状态 |
| Hallucination | 幻觉 | 产生虚假目标或错误信息 |
| Graceful Shutdown | 安全关停 | 加快战斗脱离 |
| SIGKILL | 强制终止 | 付出较大代价中断遭遇 |
| Exit(0) | 正常退出 | 安全完成指定脱离动作 |

## 9.2 技能设计要求

每张卡牌至少需要定义：

唯一ID、中文名、英文名、卡牌类型、算力成本、指令槽占用、使用条件、目标类型、攻击范围、主要效果、附加效果、资源成本、是否可缓存、是否可打断、特效模板和稀有度。

## 9.3 组合示例

**情报精准流**

Data Probe → Gradient Descent → KV Cache

通过获取情报强化针对性攻击。

**逃生控制流**

Prompt Injection → Async Jump → Firewall

干扰敌人、改变站位、阻断追击。

**超载爆发流**

Context Overflow → Token Burst → Garbage Collection

先高强度输出，再处理污染和资源代价。

**预测反击流**

Branch Prediction → Sandbox → Gradient Descent

利用情报与防御创造稳定反击机会。

# 第十章：人物和战斗视觉表现

## 10.1 总体原则

**角色负责位置与身份，特效负责行动含义。**

不要求每张卡都具有独立人物动作。

不依赖复杂骨骼动画完成战斗。

## 10.2 推荐角色形式

2D人物贴图或Q版角色结合3D场景。

Godot使用Sprite3D或其他适合的2.5D显示方式呈现人物。

战斗动作优先通过：

位置插值、缩放、闪白、淡入淡出、数据粒子、光束、扫描圈、护盾和UI反馈表现。

## 10.3 八类通用视觉动作

1. 待机与轻微浮动。
2. 移动或数据瞬移。
3. 光束与弹丸攻击。
4. 范围攻击特效。
5. 护盾与防御特效。
6. 扫描与情报揭示。
7. 受击与伤害数字。
8. 失效、崩溃和消散。

通过颜色、规模、粒子、音效和轨迹的参数变化复用通用特效。

## 10.4 角色制作层级

普通敌人采用静态贴图加通用效果。

主要角色增加有限待机、移动和受击状态。

Boss和重要剧情角色可以追加专属视觉演出。

## 10.5 低动画成本的世界观解释

AI拟人角色能够以数字化方式执行行动。

例如：

Async Jump表现为数据解构与重组。

Firewall表现为防护矩阵。

Token Burst表现为数据弹幕。

Rollback表现为历史残影回放。

这样的效果与题材自然匹配，也能够降低人物动画制作成本。

# 第十一章：搜打撤与资源经济系统

## 11.1 主要资源

探索中可获得：

Token资源、存储模块、模型权重、计算芯片、数据碎片、权限密钥、装备零件、稀有卡牌蓝图和特殊剧情物品。

这些资源既可以具有交易价值，也可以具有功能价值。

## 11.2 战利品背包

背包容量有限。

可以采用物品格数量、重量或体积等方式限制携带量。

不建议初期同时引入过多背包参数。

物资价值由市场用途、卡牌制作需求和玩家当前目标共同决定。

## 11.3 死亡惩罚

核心原则：

死亡应当造成真实损失，但不能摧毁玩家所有长期进度。

可以区分：

永久蓝图、普通实体装备、携带物资、局内临时物资和受保护物资。

永久解锁的制作蓝图不会因普通死亡失去。

实体装备和未保护战利品可以掉落或损坏。

## 11.4 保险系统

初期可以设置有限保险容量。

玩家可以保护部分高价值战利品。

保险机制必须存在成本或容量限制，避免削弱搜打撤风险。

## 11.5 负重影响

负重不仅影响移动，也可以影响战斗能力。

例如较高负重增加移动指令成本，降低脱离效率，或加入有限数量的负面状态牌。

但应避免所有惩罚叠加过度，导致玩家捡到资源后完全失去操作能力。

---

# 第十二章：追踪痕迹与全局危险系统

## 12.1 Trace系统

Trace代表玩家在当前区域留下的可追踪行为痕迹。

可能增加Trace的行为包括：

高噪音攻击、破坏设施、触发警报、使用强力干扰技能和长时间停留。

Trace影响后续遭遇权重、局部警戒和部分撤离事件。

## 12.2 信息显示

不建议向玩家完整展示隐藏遭遇概率。

可以提供定性状态：

安全、可疑、危险、极度危险。

同时通过灯光、声音、警报、异常活动频率和地图状态表达危险程度。

## 12.3 动态威胁

随着玩家行为变化，地图中的威胁分布可能变化。

例如：

警戒提高后，维护通道出现更多异常活动。

高价值区域受到更严格的守护。

撤离路线可能出现阻断、追击或异常事件。

但不能保证警戒越高就必定强制刷怪。

仍需保留成功规避与无事撤离的可能。

---

# 第十三章：撤离系统

## 13.1 撤离的定位

撤离不是菜单确认，而是本局最后一次风险决策。

玩家带着战利品进入撤离区时，不一定知道撤离是否完全安全。

## 13.2 撤离点类型

**普通撤离点**

位置固定，条件简单，路线可能较长。

**权限撤离点**

需要指定钥匙、权限或者控制设施。

**设备撤离点**

需要启动电梯、载具或通信装置。

**隐藏撤离点**

需要通过地图探索发现。

## 13.3 撤离遭遇

撤离阶段可能出现：

无事撤离、轻度遭遇、中度追击、路线阻断或少量特殊高威胁事件。

不建议每次撤离都固定触发战斗。

## 13.4 玩家应对方式

玩家可以通过：

侦查路线、制造诱饵、布置防御、降低警戒、选择其他出口和预留逃生卡等方式降低风险。

某些撤离事件的目标是坚持到撤离条件满足，而不是消灭全部敌人。

## 13.5 撤离成功反馈

撤离成功以后必须立即给予明确、安全的结算状态。

包括：

战利品展示、资源统计、稀有物资提示、任务进度和本局行为总结。

建议加入简短的战斗与风险记录，帮助玩家理解哪些行为导致后续危险上升。

# 第十四章：敌人设计

## 14.1 基础敌人类型

### Hallucination｜幻觉体

制造假目标、错误情报和虚假攻击预兆。

主要考验情报能力。

### Guardian Daemon｜守护进程

防御能力强，擅长封锁道路和保护资源。

主要考验空间控制与破防能力。

### OOM Berserker｜内存溢出狂战体

随着战斗持续逐渐进入高输出状态。

主要考验战斗速度和脱离判断。

### Prompt Injector｜提示注入者

向玩家牌组加入异常指令，或干扰已安排动作。

主要考验牌组稳定性。

### Cache Phantom｜缓存残影

复制历史行为或制造残影。

主要考验目标识别与攻击选择。

### Kernel Panic｜内核恐慌体

释放大型区域攻击，造成短暂系统故障。

主要考验时机判断、站位和指令中断。

## 14.2 敌人行为程序

普通敌人使用有限状态机或行为树。

包括：

巡逻表现、警觉、接敌、攻击、恢复和追击。

对于主要通过遭遇事件生成的敌人，不要求它们在整张地图上长期运行复杂实时AI。

## 14.3 精英和Boss设计

Boss应当具有独特的指令行为，而不是单纯增加HP。

例如：

改变攻击区域、阻断指令、产生虚假预测、限制缓存或制造环境异常。

重大攻击必须具有明确预兆。

# 第十五章：生存与异常状态

## 15.1 原则

初期不建议制作复杂的传统饥饿、口渴、睡眠系统。

可以优先突出数字生命特有的生存状态。

## 15.2 主要状态

| 状态 | 游戏效果方向 |
|---|---|
| Integrity Damage | 系统受损，降低生存能力 |
| Context Drift | 上下文漂移，影响指令稳定性 |
| Memory Leak | 内存泄漏，增加算力负担 |
| Thermal Throttle | 过热降频，影响行动频率 |
| Hallucination | 幻觉，产生不可靠信息 |
| Corruption | 数据污染，生成异常状态卡 |
| Overload | 过载，提高输出并承担副作用 |

## 15.3 异常状态卡

部分异常可以作为负面卡牌加入战斗牌组。

例如：

Corrupted Token：占据一次抽牌机会。

Context Overflow：降低手牌管理效率。

Memory Leak：持续增加算力消耗。

Garbage Collection等卡牌可以清除特定负面状态。

负面卡不能无限堆叠到让玩家彻底无法行动，应当有清晰的叠加上限与移除途径。

# 第十六章：可选避难所系统

**状态：未来扩展，不作为首版战斗原型的必要功能。**

如果后续加入避难所，应该构建一个真实可见的2.5D永久安全空间。

避难所可以包含：

数据仓库、模型修复室、算力工坊、卡牌编译台、信息终端、角色生活区和能源中心。

玩家通过撤离得到的资源解锁设施、修复装备、制作新卡和扩展角色能力。

避难所最重要的意义不是新增几个升级按钮，而是让玩家有明确的长期资源需求。

但必须防止避难所经营反过来压倒搜打撤主循环。

# 第十七章：Godot技术架构

## 17.1 技术原则

**数据驱动、逻辑与表现分离、模块化、可测试。**

卡牌效果、战斗结算和人物动画不应互相强绑定。

## 17.2 主要模块

### ExplorationController

处理玩家实时探索、容器交互、地图移动和区域触发。

### EncounterDirector

管理隐藏敌人、环境异常、遭遇池和触发条件。

### TacticalGrid

提供局部战斗空间、可通行节点、掩体和楼层连接。

### CombatPlanner

处理玩家手牌、算力、指令队列和目标选择。

### EnemyPlanner

按照敌人行为规则生成敌方指令。

### CombatSimulator

按照确定的顺序同步结算双方指令。

### CombatEventLog

记录位置变化、攻击命中、异常状态、打断与死亡。

### CombatPresenter

把战斗结果呈现为人物位移、光束、粒子、UI、音效和摄像机反馈。

### LootManager

管理战利品、掉落表与资源价值。

### ExtractionManager

管理撤离点、撤离事件与战利品结算。

### SaveManager

管理持久装备、蓝图、资源和任务进度。

## 17.3 逻辑与动画分离

战斗结算器只负责计算结果。

表现层读取战斗事件，并播放视觉反馈。

视觉表现不能决定伤害值、攻击是否命中或者角色是否死亡。

所有动画应支持加速或跳过。

## 17.4 素材复用原则

卡牌可以共用通用攻击、扫描、防御、位移和异常特效。

人物即使只有静态贴图，也必须能够完成全部战斗逻辑。

角色动作资源缺失时，使用通用替代效果。

## 17.5 原型数据组织建议

卡牌使用Godot Resource或JSON定义。

每张卡只描述自己的数据与效果。

通用效果系统负责执行伤害、移动、护盾、状态、召唤、扫描等行为。

复杂效果尽量通过组合简单效果完成。

# 第十八章：首个可玩Demo设计

## 18.1 开发目标

验证三个问题：

**战斗是否有策略性？**

**非显示怪是否能形成合理的风险判断？**

**玩家是否会主动考虑撤离而不是继续清怪？**

## 18.2 Demo范围

| 项目 | 初版规模 |
|---|---|
| 地图 | 1座废弃研究中心 |
| 角色 | 1名可控AI拟人角色 |
| 探索 | 自由移动、开门、搜容器 |
| 战斗 | 三指令同步结算 |
| 战术空间 | 8×8左右局部隐藏格子 |
| 卡牌 | 约20张 |
| 敌人 | 4种基础异常体 |
| 特效 | 8类可复用基础效果 |
| 撤离点 | 2处 |
| 主要资源 | 5～8种 |
| 任务 | 1个简单回收任务 |
| 目标时长 | 10～15分钟 |

## 18.3 推荐Demo流程

玩家从研究中心外围进入。

首先搜索低风险的维护室和普通容器。

随后接近一间停电的数据实验室。

玩家听见异常声音，发现一个半可见的AI轮廓。

通过扫描获得有限情报。

选择接敌后，进入三指令同步战斗。

玩家安排：

Async Jump → Sandbox → Token Burst。

敌人执行：

警戒 → 冲锋 → 攻击。

双方同步结算。

玩家利用掩体规避主要攻击，并取得战斗胜利。

战斗后获得高级存储模块。

由于刚才的战斗产生大量Trace，附近区域开始出现更明显的异常声音。

玩家决定不再探索高价值保险柜，而是携带战利品前往撤离点。

撤离途中触发一次潜在追击事件。

玩家可以选择：

战斗、使用诱饵、封锁通道或者绕路。

最终成功撤离，战利品进入仓库。

这段体验应当完整验证：

探索 → 情报判断 → 编排指令 → 同步结算 → 搜刮 → 危险上升 → 撤离。

# 第十九章：开发阶段规划

## 第一阶段：战斗可玩性

目标：

实现最基础的三指令同步结算。

只需一个房间、一名玩家、一个敌人和六张卡。

首先验证顺序、反制、移动与执行反馈。

## 第二阶段：空间战斗

加入隐藏格子、掩体、障碍、射线和脱离点。

测试格子方案与战术节点方案的操作差异。

## 第三阶段：完整搜打撤循环

加入容器、战利品、资源成本、撤离点、死亡损失和局外仓库。

形成一次完整可重复的游戏循环。

## 第四阶段：暗房与非显示怪

加入环境预警、半可见目标、信息层级、侦察和隐藏遭遇池。

验证非显示怪是否提升体验，而不是增加不可理解的随机惩罚。

## 第五阶段：卡牌构筑

扩展更多具有AI/代码主题的卡牌。

加入装备生成卡牌、异常状态卡、缓存、分支预测和多种流派。

## 第六阶段：地图和内容扩展

逐步加入更多复杂建筑、特殊容器、地图事件、精英敌人、Boss与剧情。

## 第七阶段：长期系统

根据实际测试决定是否加入避难所经营、角色关系、长期养成及其他模式。

多人PvP暂不作为首期目标。

# 第二十章：主要风险与设计约束

## 20.1 战斗节奏过慢

如果普通遭遇需要反复排列复杂指令，玩家会失去探索兴趣。

解决方向：

减少普通敌人战斗窗口数量，支持预设指令队列，降低弱敌复杂度。

## 20.2 随机遭遇不公平

如果怪物无预警出现并造成无法规避的致命损失，玩家容易产生挫败感。

解决方向：

保留环境预兆，允许侦查，明确脱离规则，并控制极端遭遇概率。

## 20.3 卡牌系统过度复杂

同时引入时间轴、算力、分支、并行、缓存和异常处理，可能导致学习门槛过高。

解决方向：

先验证顺序指令与同步结算，逐步增加高级机制。

## 20.4 人物动画工作量过大

复杂骨骼动画、动作衔接和多方向表现容易成为独立开发瓶颈。

解决方向：

静态Q版角色、通用特效、数据化演出和逻辑表现分离。

## 20.5 多系统缝合

卡牌、探索和撤离如果互不影响，就会成为几套独立小游戏。

解决方向：

任何重要资源与机制至少影响两个核心系统，并形成可观察的反馈。

## 20.6 资产损失过重

如果玩家永久失去不可恢复的重要卡牌，可能破坏长期成长体验。

解决方向：

区分蓝图与实体卡牌，永久能力与可损失装备，建立适当保护机制。

# 第二十一章：最终游戏愿景

本作的目标不是简单制作一款卡牌战斗游戏，也不是把传统搜打撤中的枪械替换为技能卡牌。

真正需要实现的是一套完整的风险决策体验。

玩家进入一个具有真实空间结构的2.5D世界。

危险并不完全显示。

玩家需要通过信息获取与环境判断决定行动。

遭遇敌人后，使用卡牌为AI拟人角色编排指令，并与敌人同步执行。

战斗结果不仅改变角色生命，还会影响资源、卡牌状态、追踪痕迹和后续撤离风险。

玩家最终必须判断：

**这场战斗值不值得打？**

**这个房间值不值得进？**

**这件物品值不值得带？**

**这次行动是否应该继续？**

**现在是否应该撤离？**

游戏的核心并不是让玩家不断战胜敌人，而是让玩家在有限信息、有限资源和不确定环境中，作出自己的生存决策。

---

# 最终确定的核心设计方向

**探索层：2.5D自由空间。**

**遭遇层：暗房隐藏怪、环境信息和道路事件。**

**战斗层：三指令队列与同步结算。**

**战术层：隐藏格子、掩体、位移与敌方预测。**

**卡牌层：AI、LLM和代码语义驱动的技能组合。**

**表现层：Q版静态人物、通用数据特效、低动作成本。**

**风险层：物资价值、伤势、Trace、死亡损失。**

**撤离层：不确定遭遇、路线决策与资源保护。**

**长期层：卡组构筑、装备、地图解锁，可选择加入避难所经营。**

## 游戏核心宣言

**玩家不只是操控AI角色。**

**玩家是在为AI角色编排指令，在无法完全确定未来的世界中执行决策，并承担每个决策带来的后果。**

**搜索是信息博弈。**

**卡牌是行动程序。**

**战斗是同步推演。**

**撤离是最终决策。**

这四个系统共同构成本作的游戏身份。
