# 纹理导入与缩小采样修复

本次核对实际使用的卡牌、战斗图标和背包图标，保留 PNG 原图、透明边缘、无损压缩及原始尺寸。

- 3 张卡牌插画图集、5 张品质框、6 张新战斗图标，以及 `assets/meme_items.json` 引用的 59 张柔边物品图标，共 73 张图片的导入配置补上 `mipmaps/generate=true`，并用 Godot 重新导入。
- 卡牌根控件和卡框模板改用 `LINEAR_WITH_MIPMAPS`；插画着色器改用 `filter_linear_mipmap`，采样范围按屏幕像素覆盖范围向图集单元内部收缩，避免相邻卡图串色。
- 旧的 `downloaded_20261011` 图标已有正确导入设置；`handheld_skin.gd` 的通用图标修复、背包图标运行时生成 mipmaps 的处理仍有效。新战斗图标的直接加载路径没有沿用这些处理，因此需要补全素材自身的导入设置。
- 像素战场及原有 32/64 像素图标的导入方式保持原样；本次没有修改全局纹理过滤。

Godot Compatibility 渲染器检查了上述 73 张及旧图标 15 张的实际导入纹理：88 张均含 mip 层且尺寸保持原样。真实战斗手牌、悬浮预览、品质框、新战斗图标和旧通用图标加载路径检查通过，没有出现着色器编译错误。检查文件和日志位于 `预览/texture_import_20261017/`；测试进程退出时有 2 个 ObjectDB 实例未释放的警告。

修改前素材、导入配置和卡牌代码已备份到 `备份/20261017_texture_import_before/`。正在运行的游戏仍持有旧资源，重新启动游戏后载入新导入结果。

Godot 对 mipmaps 和缩小过滤的说明见 [Importing images](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)。
